# КидГоу 🎈

**Выберите настроение — мы соберём ваш день.**

Mobile-first веб-приложение для родителей: не каталог детских мест, а персональный семейный планировщик.
Пользователь выбирает, кто идёт, сколько есть времени, настроение, бюджет и транспорт — и получает
готовое «приключение»: несколько мест рядом, время каждого шага, дорогу между ними, бюджет на семью,
возраст, подходит ли погода и почему это подходит именно этой семье.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:3000 — открывайте в мобильном режиме DevTools (375–430 px)
npm run build && npm start
npm run eval                      # оценка движка: 11 520 прогонов + 77 сценариев, 0 нарушений (идёт в CI)
npm run audit                     # аудит сценариев и условий: ~30 000 прогонов матрицы, обновляет docs/scenarios.md
npm run audit:quick               # то же в урезанном виде (идёт в CI)
npm run audit:areas               # «округ — граница» во всех 11 округах и на всех экранах: подбор, «для вас», замена шага, приключения (идёт в CI)
python3 scripts/smoke-flows.py http://localhost:3000   # сквозные сценарии в браузере (Playwright)
python3 scripts/e2e-layout.py http://localhost:3000    # вёрстка: все экраны × телефоны/планшет/ноутбук, без горизонтального «выезда»
```

Node 20+. Внешние сервисы не обязательны: данные — в mocked data layer, фото — с CDN Unsplash,
карта — бесплатные тайлы (цепочка OpenFreeMap → OSM → OSM.de → OSM-FR → Esri, без ключа; выбирается первый
ответивший источник и запоминается; источники, которые вместо тайлов отдают одну картинку-заглушку, вроде «API KEY
REQUIRED» у CARTO, отбрасываются автоматически; на карте есть кнопка «Сменить карту»). Если ни один не открылся, показывается виджет Яндекс Карт (работает там, где иностранные
тайлы недоступны), а если и он недоступен — схема округов и расстояний без подложки; есть кнопка «Повторить».

| `/api/places`, `/api/places/[slug]`, `/api/adventures`, `POST /api/plan` | Публичный API поверх того же слоя данных |

### Контекст: где вы, какая погода, кто идёт

- **Где ищем** (`src/lib/location.ts`, `LocationSheet`): по умолчанию **«Вся Москва»** — точка выезда не нужна, дорога
  не ограничивается и не влияет на выдачу. Хотите под себя — выберите округ (ЦАО, САО, СВАО, ВАО, ЮВАО, ЮАО, ЮЗАО,
  ЗАО, СЗАО, Зеленоград, Новая Москва — «условный» центр округа, режим `area`) или точный адрес / GPS / «Дом»
  (режим `exact`). Режимы: `any` — только места Москвы (не Подмосковье), без дороги и расстояний; `area` — дорога считается
  грубо («≈ N мин»); `exact` — как раньше. Сценарии «рядом» в режиме «Вся Москва» просят выбрать место.
- **Округ — это граница, а не «чуть ближе»** (`src/lib/moscow.ts`, `areaScope`): выбран СЗАО — основные места (парк, музей,
  площадка, активное, животные) берутся **только из СЗАО**, а кафе и магазины — ещё из соседних округов. Округ места
  определяется без внешних сервисов: ядро ≈ МКАД делится по опорным точкам районов, за МКАД заданы Зеленоград, Новая Москва,
  Бутово, Солнцево, Некрасовка; у отдельных мест округ уточнён вручную (`OKRUG_OVERRIDE`). Подходит ли место *типу* ситуации
  («Опыты и наука» — музей/лаборатория, а не парк), решает `coreFit`.
- **Если в округе под ситуацию ничего нет** (`src/lib/recommend/area.ts`, `AreaGap`): приложение так и говорит — «В СЗАО под
  это ничего нет» — и предлагает выход: *то же самое в другом округе* (с временем в пути) или *что подойдёт в СЗАО* (другие
  ситуации, которые в этом округе реально работают, например прогулка). Ссылки «расширить на ближайшие округа» (`wide=1`) и
  «показать и не совсем по теме» (`loose=1`) — осознанный выбор пользователя, а не молчаливая подмена.
- **То же правило везде, не только в подборе дня** (`src/lib/area-fit.ts`, один набор функций `okrugOf`/`tierOf`): «Для вас» и
  «Популярное в СЗАО» на главной (свои места первыми, соседние — следом, из другого конца города — только если рядом почти ничего
  нет), список на карте, поиск (место из округа поднимается выше), **замена шага** (занятие меняется на занятие из того же округа,
  кафе — из него или соседнего), **готовые приключения** (подпись «Всё в ЗАО» / «ЦАО — не в ЗАО», порядок, фильтр «📍 В ЗАО»);
  у карточек мест из другого округа в подписи дороги стоит его название («ЦАО · ≈ 38 мин»).
- **Покрытие округов** (`src/lib/nearby.ts`): каталог неравномерен (ЦАО — 39 мест, ЮВАО — 4), поэтому для любого выбранного
  округа, где в каталоге меньше 14 основных мест, фоном подгружаются места OpenStreetMap внутри округа (парки, площадки, музеи,
  зоопарки, катки, театры, библиотеки; помечены «данные не проверены», рейтинг скрыт). Если связи нет — честное «в округе пока мало
  мест» и привычные выходы (другой округ / другая ситуация).
  Поиск города/посёлка/улицы: офлайн-справочник ~40 городов области + онлайн Nominatim → Photon, булавка на карте
  (`MapPicker`), GPS. `travelBetween` — оценка, учитывает шоссе: за городом едем быстрее, чем по Москве.
- **За МКАД** (`isSuburban`, > 24 км от центра): по умолчанию «машина»; если рядом мало подходящего, движок сам
  расширяет радиус (×1,5/×2,2/×3,2) и честно пишет об этом; места рядом с домом подтягиваются из OpenStreetMap.
- **Места из OpenStreetMap** (`src/lib/osm.ts`, `src/lib/nearby.ts`, `src/lib/data/dynamic.ts`): если в 8 км от точки
  меньше 14 мест каталога, фоном запрашиваем Overpass (парки, площадки, музеи, зоопарки, катки, аквапарки, театры,
  библиотеки, кафе…), превращаем в `Place` с `confidence: "osm"` и добавляем в выдачу (`PlannerInput.extraPlaces`).
  Кэш в браузере по ячейкам ~4 км на 7 дней; общая ссылка на день с такими местами подтягивает их по id. Режим и цены
  берутся из тегов OSM или по умолчанию для типа места, отзывов нет — рейтинг в интерфейсе скрыт.
- **Погода по часам** (`src/lib/forecast.ts`): Open-Meteo без ключа, кэш 30 мин, при недоступности — последний
  прогноз или честно помеченный примерный. `?wx=rain|rain15|sun|cold|heat|snow` — тестовая погода.
- **Семья** (`src/lib/store.ts`): никаких демо-детей по умолчанию; возраст из даты рождения; хотелки, «были»,
  оценки «Как прошло?» и недавно показанное — сигналы для движка.

### Recommendation engine v2 (без LLM как источника истины)

1. **Контекст дня**: дата (вечером — завтра), окно до «домой к…», прогноз, точка выезда.
2. **Жёсткие фильтры**: возраст всем детям (иначе честно — «часть мест для старшего»), время в пути, бюджет,
   ограничения сценария (только под крышей, тихо, коляска…), «не понравилось».
3. **Скоринг**: настроение, интересы каждого ребёнка, близость в минутах, погода, хотелки/история, ротация по дню.
4. **Сборка по слотам** до заполнения окна: якорь → еда (поближе) → второе занятие (для непокрытых интересов) → бонус.
5. **Порядок шагов перебором**: часы работы на момент прибытия + погода в окне каждого шага + дорога;
   прогулка — в сухое окно, с объяснением «гуляем до дождя».
6. **Набор планов**: разнообразие (MMR) + «неожиданная идея», крытая замена для уличных шагов, «что взять».
7. **Нет результата** → подсказки, какое ослабление условий даст хороший день.

Условия действуют сильно и измеримо: погода по часам, температура (мороз/жара), сезон, будни/выходные, время суток,
дневной сон малыша, возраст каждого ребёнка, бюджет, транспорт (парковка/метро), настроение, интересы.

`npm run eval` проверяет: 0 нарушений (закрыто к приходу, не по возрасту, вне бюджета, улица под дождём, далеко),
каждый из 77 сценариев даёт план, длину дня и разнообразие выдачи; **чувствительность** — меняем одно условие
(погода, возраст, бюджет, настроение, точка, транспорт, сезон, интерес) и требуем, чтобы план менялся; **загород** —
720 запусков из 10 городов области без пустых выдач; **OSM** — фикстура Overpass для посёлка с пустым каталогом.

`npm run audit` (`scripts/audit-scenarios.ts`) — аудит сценариев: у каждого из 77 свой рецепт (нет дублей), каждый
достижим с главной, прогон матрицы «сценарий × состав семьи × погода × бюджет × место (вся Москва / округ / адрес) × день»
без жёстких нарушений, пустые выдачи (доли процента) всегда с подсказкой, что ослабить; **влияние условий** — доля
запусков, где смена одного условия меняет план (дождь, мороз, жара, возраст, бюджет, машина, место, время суток, день).
Итоговая таблица сценариев и влияния условий — в `docs/scenarios.md` (генерируется).

Браузерные проверки (Playwright, нужен `npm run dev` или статическая выгрузка): `python3 scripts/smoke-flows.py`,
`scripts/e2e-suburb.py` (посёлок за МКАД: поиск адреса → места из OSM → план → общая ссылка), `scripts/e2e-map.py`
(карта с подменёнными тайлами, цепочка запасных вариантов и выбор точки булавкой), `scripts/e2e-layout.py` (все экраны на
320–1536 px: нет горизонтальной прокрутки, фиксированные панели помещаются по высоте, на внутренних экранах есть «назад»,
в знакомстве кнопка «Дальше» видна без прокрутки), `scripts/e2e-okrug-osm.py` (все 11 округов: подставные данные OSM из
`scripts/fixtures/okrug-osm.json` лежат во ВСЕХ округах, а в план попадают только места выбранного).

### Навигация
Стрелка «назад» есть на каждом внутреннем экране (`BackButton`, `src/lib/nav.ts`): приложение ведёт собственный стек переходов,
поэтому «назад» возвращает туда, откуда пришли (а не выбрасывает из приложения), а если идти некуда — на главную или во вкладку.
Переключение вкладок нижней панели обнуляет стек. Жест «свайп назад» работать продолжает, но больше не единственный способ.

### Сценарии

`src/lib/scenarios.tsx` — 77 жизненных ситуаций (погода, время, состав, повод, настроение, бюджет) как данные:
параметры + ограничения для движка + «уместность сейчас». Главная показывает 8 самых уместных, `/scenarios` — все; на главной они слегка ротируются по дню недели, месяцу и времени суток.
Полный расклад (группа, рецепт, ограничения, когда выше всего на главной) — `docs/scenarios.md`.

AI-слой (`nlu.ts`, `explain.ts`) работает только поверх базы: превращает фразу в фильтры и формулирует
объяснения из фактов плана. Интерфейсы совместимы с LLM-провайдером (function calling), но места
он не придумывает.

### Design system

Снята с визуального референса: светлый тёплый фон `#FBFAF7`, белые карточки с мягкой тенью, радиусы 18–28 px,
фуксиевый primary `#FF2E88`, категориальная палитра (жёлтый/зелёный/розово-красный/фиолетовый/голубой/оранжевый),
крупные заголовки 24–32 px weight 800–850, пухлый разноцветный логотип, залитые иконки категорий.
Токены — в `src/app/globals.css` (`@theme`), категории/сценарии/интересы — в `src/lib/catalog.tsx`.

### Состояния

loading (скелетоны маршрутов), empty (иллюстрированные), error (`error.tsx`), no results (поиск, планировщик
с подсказками), offline (баннер + service worker + `offline.html`), geolocation denied (карта),
closed place (статус «Закрыто · откроется в…»), bad weather (дождевые приключения первыми, баннер «под крышей»),
нет фото (яркая иллюстрация вместо серого плейсхолдера), нет тайлов карты (иллюстрированная карта).

### Производительность и SEO

SSG для всех мест и приключений (`generateStaticParams`), ISR главной (30 мин), `next/image` с CDN-лоадером
(ресайз/AVIF/WebP на стороне CDN), lazy-загрузка, MapLibre подгружается динамически только на `/map`,
`optimizePackageImports` для иконок. Metadata, OpenGraph, JSON-LD (TouristAttraction/Museum/Restaurant, TouristTrip),
`sitemap.xml`, `robots.txt`, чистые slug'и (`/places/skazochny-les`, `/adventures/den-dinozavrov`). PWA: manifest,
иконки, service worker.

## Подключение production-инфраструктуры

- **БД**: `npm i -D prisma && npm i @prisma/client`, `DATABASE_URL`, `npx prisma migrate dev`; реализовать
  `DataRepository` через Prisma (гео-запросы — `ST_DWithin` по колонке `geom`). UI менять не нужно.
- **Auth**: Supabase Auth / Clerk — `Family.id = user.id`; `store.ts` синхронизирует детей, хотелки и сохранённые планы.
- **Storage**: фото мест в Supabase Storage / S3; поменять базу URL в `src/lib/image-loader.ts`.
- **Карта**: `NEXT_PUBLIC_MAP_STYLE_URL` — любой MapLibre-совместимый стиль (MapTiler, Mapbox и т.п.).
- **Погода**: заменить мок в `src/lib/weather.ts` на Open-Meteo / Яндекс.Погоду.
- **Аналитика/мониторинг**: `src/lib/analytics.ts` (PostHog), `src/app/error.tsx` — точка для Sentry.
- `NEXT_PUBLIC_SITE_URL` — домен для sitemap/OG.
