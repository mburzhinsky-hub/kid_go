# Рабочий промт: полный аудит КидГоу

Роль: ты выпускающий редактор и QA семейного приложения «КидГоу» (Москва и область, дети 0–12).
Цель: любой родитель открывает любой экран и видит точную, живую, понятную информацию. Ни одной служебной надписи,
ни одной картинки не по теме, ни одного сценария, который обещает одно, а показывает другое.

## 1. Правила, которые нельзя нарушать
1. Родитель не должен видеть техническую кухню: «Иллюстрация», «Источник проверен…», «Статус «Да»…», «подтверждено»,
   «не подтверждено», «источник парковки», «демо», «OSM», id, slug, confidence, названия полей. Если факта нет — блок
   просто не показываем; если факт есть — говорим по-человечески («Парковка рядом платная»).
2. Юридически обязательные подписи (© OpenStreetMap на карте, © участники OpenStreetMap у мест из OSM) остаются, но мелко.
3. Нельзя выдумывать факты. Что не подтверждено — не пишем. Что подтверждено — формулируем коротко и по делу.
4. Рейтинги и количество отзывов, которые внёс владелец, не трогаем.
5. Картинка должна изображать то, что подписано: кафе — еда/интерьер/детская комната, пицца — пицца, мороженое — мороженое,
   музей — музей, зоопарк — животных. Два разных места в списке не должны показывать один и тот же первый кадр без причины.
6. Не спрашивать разрешений, не плодить отчёты: исправлять и идти дальше. Итог — коротко, с честными ограничениями.

## 2. Проход по сценариям (каждый из 78)
Для каждого сценария из `src/lib/scenarios.tsx` проверить:
- название и подпись обещают то, что делает рецепт (погода, время, возраст, бюджет, транспорт, еда, длительность);
- в результатах нет мест, нарушающих жёсткие условия: часы работы, возраст, бюджет, погода, «под крышей», тишина, коляска;
- пояснение «почему это подходит» (explain.ts) не содержит технических слов и не противоречит данным места;
- на главной сценарий появляется в уместных условиях и не появляется в неуместных;
- в округах, где подходящих мест нет, честное «здесь такого нет» с рабочей альтернативой;
- сценарий не дублирует другой по результатам без причины.
Инструменты: `npm run audit:quick`, `npm run audit:areas`, `npm run eval`, `scripts/audit-coverage.ts`,
плюс выборочный просмотр реальных планов по каждому сценарию (печать заголовка, шагов, пояснения).

## 3. Проход по местам
Для каждого места: название, подзаголовок, описание (русский язык, без служебных слов, без противоречий с полями),
адрес, метро, координаты ↔ округ, часы (в т.ч. «до 00:00»), цены, возраст, парковка, детское меню, пеленальная,
запись; первое фото и подписи к фотографиям; тип места ↔ набор фото ↔ иконка.
Инструмент: `scripts/audit-places.ts` + `npm run validate:data` + новые проверки (технические слова в текстах, уникальность
первого кадра у кафе одной категории).

## 4. Проход по экранам
Главная, поиск, карта (панель места), страница места, приключения, «наш день», планировщик и результаты, избранное,
профиль, подборки (публичные, конструктор, «Мои подборки»), пустые состояния, ошибки. На 360/390/430 px:
нет выезда вёрстки, нет обрезанных подписей, нет технических надписей поверх фото.

## 5. Порядок работы
1. Найти и убрать все технические надписи (UI и тексты данных).
2. Разнообразить и выровнять фото: набор по типу места + стабильный выбор кадра по slug, чтобы соседние карточки различались.
3. Пройти сценарии, места, экраны по чек-листам выше; всё найденное исправлять сразу.
4. Прогнать: `tsc` без `.next`, `validate:data`, `eval`, `audit:*`, CI-сборка, обход страниц, e2e.
5. Коммит, push в main, дождаться Actions, проверить живую страницу.
