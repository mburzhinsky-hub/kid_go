# Промт: личные кабинеты Kids Go (ник + фото, без почты и пароля)

Ты работаешь в репозитории `mburzhinsky-hub/kid_go` (Kids Go: мобильное PWA для родителей детей 1–12 лет, Москва и область; Next.js 16, React 19, TypeScript, Tailwind 4, zustand, статический экспорт).
**Сначала прочитай `AGENTS.md`**: в этой версии Next.js есть ломающие изменения. Перед кодом открой нужные разделы `node_modules/next/dist/docs/` и учитывай предупреждения об устаревших API.

## 1. Цель

Сделать личные кабинеты, в которых человек **без почты, телефона и пароля**: выбирает ник и картинку профиля, создаёт подборки мест, делится ими и сохраняет чужие. Данные нужны минимальные, поэтому и ответственности по ним меньше. Перенос на хостинг и своя база — часть задачи.

Что должен получить пользователь:
1. Создать кабинет за 20 секунд: ник + аватар (готовый или своё фото).
2. Делать подборки трёх видов: **личная** (видит только автор), **по ссылке** (видит тот, у кого ссылка), **публичная** (видна на странице автора и в каталоге).
3. Делиться ссылкой на подборку и на страницу автора (`/@ник`) с нормальным превью в Telegram, WhatsApp, Instagram.
4. «Хочу сюда», «Были» и сохранённые подборки привязаны к кабинету и доступны с другого устройства.
5. Видеть простую статистику своих подборок (просмотры, сохранения, «хочу сюда»).
6. Удалить кабинет и все свои данные одной кнопкой; выгрузить свои данные в JSON.

## 2. Что уже есть в коде (не ломать, развивать)

- `src/lib/social/` — слой данных подборок. `repo.ts` написан так, что UI вызывает **только** его функции и хуки (`createCollection`, `updateCollection`, `publishCollection`, `deleteCollection`, `saveCollection`, `becomeCreator`, `resolveAll`, `usePublicCollections` и др.), а реализация сейчас локальная (zustand + localStorage). **Сигнатуры сохраняем, меняем тела**: оптимистично обновляем стор, затем отправляем запрос на сервер.
- `types.ts` повторяет `prisma/schema.prisma` (User, CreatorProfile, Collection, CollectionItem, CollectionSave, PlaceIntent, Referral, AnalyticsEvent). Модель данных берём оттуда, адаптируем под MySQL.
- `identity.ts` — анонимный id устройства (localStorage + cookie). `share.ts` — ссылки; сейчас созданная на устройстве подборка переезжает **снимком внутри ссылки** (`/c/?d=…`). `transfer.ts` — перенос хотелок ссылкой (`/import`).
- Страницы: `src/app/[handle]/page.tsx` и `[handle]/[slug]/page.tsx` (демо-авторы, `generateStaticParams`), `/c`, `/collections`, `/collections/new`, `/collections/edit`, `/import`. Админка контента `src/app/admin` и `src/app/api` исключаются из статической сборки.
- Лимиты в `repo.ts`: `MAX_ITEMS=30`, `MAX_NOTE=240`, `MAX_TITLE=100`. Валидация ника — `validateHandle`.
- Сайт собирается как статика (`output: "export"`, `trailingSlash: true`), пути берутся из `NEXT_PUBLIC_BASE_PATH` (сейчас пусто) и `NEXT_PUBLIC_SITE_URL` (`https://kids-go.fun`).
- CI: `.github/workflows/quality.yml` (на PR) и `pages.yml` (деплой при слиянии в `main`). Проверки: `npm run typecheck`, `validate:data`, `eval`, `audit:*`, e2e-скрипты Playwright в `scripts/`.

## 3. Хостинг и ограничения среды (это решено, не обсуждаем)

- Хостинг reg.ru Host-0, панель ispmanager: **PHP 8.3** (доступны 8.0–8.5), **MySQL 8.0.25**, база `u3674946_default` уже создана (`127.0.0.1:3306`), диск 13 ГБ, трафик и CPU без лимитов, до 7 сайтов, cron есть. Домен `kids-go.fun`, DNS у reg.ru.
- Бэкенд: **чистый PHP 8.3 + PDO (MySQL), без Composer и фреймворков**, JSON API. Один входной файл `api/index.php` с маршрутизатором, код по файлам в `api/src/`. Все запросы — подготовленные выражения, `utf8mb4`.
- Данные пользователей хранятся на российском хостинге (152-ФЗ).
- Статический фронтенд остаётся Next.js static export и выкладывается на тот же хостинг, чтобы сайт и API были на **одном домене и одном IP** (`https://kids-go.fun/api/…`). Причины: нет CORS, и Safari не режет cookie/хранилище, как для «чужого» API. GitHub Pages остаётся запасным вариантом до переключения DNS.
- Секреты (пароль БД, ключ подписи, админ-токен) лежат в `api/config.php` **вне репозитория** (создаётся на хостинге, в репозитории только `config.example.php`). Загрузки (`uploads/`) — отдельная папка, где выполнение PHP запрещено.

## 4. Аккаунт: ник и пароль, без почты

**Решение владельца:** человек сам придумывает ник и пароль; почту и телефон не просим. (Первоначальная схема «секретный ключ + ссылка восстановления» заменена: ник и пароль понятнее и позволяют войти с любого телефона.)

**Создание.** Шит «Создать кабинет»: ник, пароль (8–64 символа; отсеиваем самые частые пароли, пароль с ником, «11111111»), имя для показа (необязательно), аватар, один чекбокс согласия с правилами и политикой. Ловушка для ботов (скрытое поле).

**Вход по устройствам.**
- `POST /accounts` и `POST /sessions` возвращают токен входа (32 случайных байта, base64url). На сервере хранится только `SHA-256(токен)` в таблице `sessions` (устройство, дата, срок до 400 дней со скользящим продлением, не более 10 устройств).
- Клиент кладёт токен в `localStorage`, а сервер ставит такой же в cookie `kg_session` (`HttpOnly; Secure; SameSite=Lax`). Так вход переживает очистку `localStorage` в Safari; от CSRF защищает `SameSite=Lax` и то, что тела запросов — только `application/json`.
- Пароль — `password_hash` (bcrypt), перед проверкой несуществующего ника всё равно считаем хэш (одинаковое время и одинаковый ответ «Неверный ник или пароль»).
- Перебор: 5 неудачных входов на ник и 20 на адрес за 15 минут → 429; счётчик считает только неудачи.
- Выход на этом устройстве / на всех; список устройств; смена пароля (остальные устройства выходят); удаление кабинета с подтверждением паролем.
- **Забытый пароль восстановить нельзя** (нет почты). Предупреждаем при регистрации. Позже — необязательная почта «для восстановления» (в `users` оставлено место под `email_hash`).

**Ник.** Уникальный без учёта регистра, 3–30 символов, `[a-z0-9._-]`, начинается и заканчивается буквой или цифрой, без повторяющихся знаков, список зарезервированных (`admin`, `api`, `kidsgo`, ники демо-авторов…). Смена ника не чаще раза в 7 дней, старый освобождается через 30 дней (этап позже). Занятость проверяется на лету (`GET /api/v1/handles/check`).

**Аватар.** Готовые эмодзи с цветом подложки (как сейчас). Своё фото (этап позже): сервер сам проверяет содержимое, обрезает в квадрат, удаляет EXIF, сохраняет 256 и 96 пикселей; подсказка «Не загружайте фото детей».

## 5. Подборки и «Хочу сюда»

- Видимость: `PRIVATE` / `UNLISTED` / `PUBLIC`; статус `DRAFT` / `PUBLISHED` / `HIDDEN` (скрыто модерацией).
- Идентификаторы: у любой подборки случайный несоседний id (10 символов), его нельзя угадать перебором. Публичные дополнительно живут по `/@ник/слаг`. `UNLISTED` — только по `/c/<id>` и не попадает в каталог и sitemap (`noindex`).
- Лимиты: до 50 подборок на кабинет, места/заметки/название — как в `repo.ts`. Места ссылаются на `place_id` (slug) из каталога сайта; сервер проверяет, что такой slug есть в списке допустимых (генерируется при сборке в `api/data/places.json`).
- **«Хочу сюда», «Были», обратная связь и сохранённые подборки** — серверные для кабинета (`place_intents`, `collection_saves`), с синхронизацией при входе: анонимные записи устройства (`claimAnonymous`) переезжают в кабинет. Без кабинета всё работает локально, как сейчас.
- `/import` и перенос ссылкой остаются для тех, у кого нет кабинета; для владельцев кабинета заменяется ссылкой восстановления.
- **Дети.** Сервер **никогда не получает** имена, возраст и интересы детей, id семьи и профили детей. Подборка хранит только диапазон возраста, который автор выбрал сам. Добавь автотест, который перехватывает все запросы к `/api/` и падает, если в теле есть поля семьи/детей.

## 6. API (JSON, `/api/v1`)

Формат ошибок: `{ "error": { "code": "…", "message": "по-русски" } }`, корректные HTTP-коды. Все изменения — только `POST/PUT/PATCH/DELETE` с ключом.

| Метод и путь | Что делает |
|---|---|
| `POST /accounts` | создать кабинет (ник, пароль, имя, аватар, согласие) → профиль + токен входа |
| `POST /sessions` · `DELETE /sessions/current` · `DELETE /sessions` | вход по нику и паролю · выход здесь · выход на всех устройствах |
| `GET /me/sessions` · `POST /me/password` | список устройств · смена пароля |
| `GET /me` · `PATCH /me` | мой профиль / смена имени, ника, аватара, bio |
| `POST /me/avatar` | загрузка фото |
| `GET /me/export` · `DELETE /me` | выгрузка JSON · удаление кабинета и всех данных |
| `GET /handles/check?h=` | свободен ли ник |
| `GET /authors/:handle` | публичный профиль + публичные подборки |
| `GET /collections?mine=1` | мои подборки (все виды) |
| `POST /collections` · `PUT /collections/:id` · `DELETE /collections/:id` | создание, правка, удаление |
| `GET /collections/:id` | подборка (PRIVATE — только автору, UNLISTED/PUBLIC — по id) |
| `GET /collections?public=1&limit=&cursor=` | публичный каталог |
| `PUT/DELETE /collections/:id/save` | сохранить / убрать из сохранённых |
| `PUT/DELETE /intents/:placeId` | «Хочу сюда» / «Были» / обратная связь |
| `GET /me/intents` · `GET /me/saves` | синхронизация при входе |
| `POST /events` | пачка аналитических событий (до 50, без персональных данных) |
| `GET /me/stats` | статистика моих подборок |
| `POST /reports` | пожаловаться на подборку или автора |

Правила: ответ без лишних полей (никогда не отдаём хэши и чужие `id` устройств); пагинация курсором; `ETag`/`Cache-Control: no-store` для приватного; публичные GET кэшируются коротко.

## 7. База данных (`api/migrations/NNN_*.sql`, идемпотентные, раннер `api/migrate.php`)

Таблицы (`utf8mb4`, `InnoDB`, внешние ключи с `ON DELETE CASCADE` для данных пользователя): `users` (id, handle, handle_lc UNIQUE, display_name, avatar_kind/avatar_value/tint, bio, key_hash UNIQUE, email_hash NULL, status, created_at, handle_changed_at, last_seen_at), `collections`, `collection_items`, `collection_saves`, `place_intents`, `events` (с ротацией, храним ≤ 90 дней), `reports`, `rate_limits` (ключ, окно, счётчик), `handle_holds` (освобождаемые ники), `admin_actions` (журнал модерации). Индексы: по `(user_id, updated_at)`, `(visibility, status, published_at)`, `handle_lc`. Основа — `prisma/schema.prisma`; Prisma на хостинге **не используем**, схему поддерживаем SQL-миграциями.

## 8. Защита от спама и атак

- Лимиты (IP + ключ, таблица `rate_limits`): создание кабинета — 3 в сутки с IP; подборок — 10 в сутки; загрузок фото — 5 в сутки; жалоб — 20 в сутки; события — 120 в минуту; любой запрос без ключа — разумный общий потолок. При превышении — `429` с `Retry-After`.
- Honeypot-поле и минимальная задержка в форме создания кабинета; отказ при пустом `User-Agent`.
- Валидация и обрезка всех строк на сервере, экранирование при выводе; заголовки `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`; `.htaccess` в `uploads/` запрещает исполнение скриптов; максимальные размеры тела запроса.
- Логи без ключей и без тел запросов; ключи нигде не пишутся в логи.

## 9. Модерация

- Кнопка «Пожаловаться» на подборке и на странице автора (причины: неприемлемое, чужое фото/ник, реклама/спам, дети на фото, другое).
- Автоскрытие подборки/аватара после 3 жалоб от разных устройств (до проверки), уведомление автору при следующем входе.
- Админка (`/admin/moderation`, **не** входит в публичную статику): вход по токену из `config.php` (+ `Basic`-защита в `.htaccess`), список жалоб, действия: скрыть подборку, заменить аватар на стандартный, заблокировать ник, вернуть. Все действия пишутся в `admin_actions`.
- Страница «Правила сообщества» (что нельзя) и контакт для жалоб (адрес даст владелец).

## 10. Страницы и превью (важно для статики)

- Демо-авторы остаются статическими. Для **реальных** пользователей `/@ник` и `/c/<id>` создаются на лету. Решение: единая статическая «оболочка» страницы + данные из API на клиенте; правило в `.htaccess` отправляет эти пути в `api/page.php`, который берёт готовый HTML оболочки и **подставляет `<title>`, `og:title`, `og:description`, `og:image`** для превью (картинка — обложка/аватар). Для `PRIVATE` и неизвестных id — `404` и `noindex`.
- Публичные подборки и авторы попадают в `sitemap.xml` (генерируется cron-скриптом раз в час).
- Старые ссылки `/c/?d=…` (снимок внутри ссылки) продолжают открываться.

## 11. Интерфейс (мобильный первым делом)

- Вход в кабинет: вкладка «Профиль» → «Создать кабинет» (если нет) или «Мой кабинет» (если есть). Шит с ником и аватаром, подсказки по-русски, ошибка ника показывается на лету.
- «Мой кабинет»: шапка (аватар, ник, имя, «Поделиться страницей»), вкладки «Мои подборки» (с видом видимости и статистикой на карточке), «Сохранённое», «Настройки» (имя/ник/аватар, ссылка восстановления с QR, сменить ключ, правила, политика, удалить кабинет, скачать данные).
- Редактор подборок (`CollectionBuilder`) получает переключатель видимости с пояснением каждого пункта и кнопкой «Скопировать ссылку».
- Состояния: загрузка, пусто, ошибка сети (очередь записи без потери данных и повтор), лимиты (понятное сообщение).
- Требования к вёрстке: шрифт полей ≥16px, экран не «гуляет» по горизонтали, кнопки ≥44px, тёмная/светлая тема не меняются (как сейчас).
- Название везде — **Kids Go**.

## 12. Право и тексты

- Страницы `Политика конфиденциальности` и `Правила сообщества` (простым языком): что храним (ник, имя, аватар, подборки, «хочу сюда», технический ключ), где (хостинг в РФ), как удалить, срок хранения событий, технические cookie (никакой рекламы и сторонних трекеров).
- Согласие на обработку при создании кабинета: чекбокс, дата и версия согласия сохраняются.
- Данные и фото детей запрещены правилами; жалобы обрабатываются в течение суток.
- Тексты юридические — только как рабочий черновик, **помечаем, что их надо показать юристу перед запуском**.

## 13. Выкладка и переключение

1. `.github/workflows/deploy-hosting.yml`: при слиянии в `main` собирает статику, запускает проверки, заливает `out/` и `api/` на хостинг по SFTP/FTP (`lftp`/`rsync`), прогоняет `api/migrate.php` по защищённому URL/токену. Доступы — **только GitHub Secrets** (`HOSTING_HOST`, `HOSTING_USER`, `HOSTING_PASS` или ключ, `MIGRATE_TOKEN`). Не коммить секреты.
2. Сначала всё проверяется на техническом адресе хостинга (поддомен от reg.ru), затем в зоне DNS домена A-записи меняются с адресов GitHub на IP хостинга, SSL выпускается в ispmanager (Let's Encrypt). После этого включается HSTS. `public/CNAME` удаляется из деплоя на хостинг, GitHub Pages остаётся как резерв.
3. Откат: вернуть A-записи на GitHub Pages (резервная сборка с локальным слоем данных продолжает работать).
4. Резервные копии: cron раз в сутки `mysqldump` + архив `uploads/`, хранение 7 копий, на хостинге вне `www`.

3. **Интерфейс кабинета:** создание кабинета, «Мой кабинет», настройки, редактор видимости.
4. **Публичные страницы и превью:** `/@ник`, `/c/<id>`, `api/page.php`, sitemap.
5. **Жалобы и модерация, статистика автора.**
6. **Удаление и выгрузка данных, политика, правила, согласие.**
7. **Выкладка на хостинг и переключение домена** (по чек-листу из раздела 13).

## 15. Критерии готовности и проверка

- `npm run typecheck`, существующие `validate:data`, `eval`, `audit:*` остаются зелёными; `php -l` на всех файлах API без ошибок.
- Playwright (мобильный профиль iPhone): создать кабинет → создать подборку трёх видов → открыть ссылку в **другом** контексте браузера (без ключа): `PRIVATE` недоступна, `UNLISTED` открывается по id, `PUBLIC` видна в каталоге и на странице автора → войти по нику и паролю в третьем контексте → удалить кабинет: данные и файл аватара исчезли, ссылки отдают 404.
- Проверка лимитов (429), занятого ника, кривых данных (слишком длинные строки, чужой `place_id`, неподдерживаемый файл вместо фото), попытки изменить чужую подборку (403).
- Проверка приватности: в запросах к API нет полей семьи и детей; в ответах нет `key_hash`, `email_hash`, чужих anonymous id.
- Превью: в HTML страницы `/@ник` и `/c/<id>` (ответ без JS) есть корректные `og:*`.
- `scripts/e2e-layout.py`: нет горизонтального переполнения на всех размерах; поля ввода ≥16px.
- Нагрузочная проверка простая: 50 параллельных чтений каталога укладываются в 300 мс на запрос.
